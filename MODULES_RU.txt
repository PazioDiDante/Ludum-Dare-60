Игровые модули

scrap_cost в Create каждого obj_module_* задаёт стоимость сборки в scrap.
Переработчик возвращает половину этой стоимости. Подробности: ASSEMBLER_RU.txt.

Список выпадения: scripts/scr_campaign/scr_campaign.gml, game_module_types().
В каталоге 16 объектов: восемь исходных, шесть модулей второго тира и два переходника.
Все находятся в папке Modules, их родитель — par_module.
Каждый Create вызывает event_inherited(), затем задаёт имя, stats.energy,
stats.weight, stats.heat, stats.stability, drop_weight, module_color и shape.
drop_weight — относительный вес: 2 выпадает вдвое чаще 1, 0 отключает тип.
Дробные веса допустимы: у big boy вес 0.5. unlock_after_orders задаёт число
сданных больших заказов до появления типа в случайном луте: 0 у старых, 3 у новых.
Проверка выполняется при открытии/разборе донора, включая роботов.
Каталог лаборатории показывает все типы независимо от прогресса игры.
Характеристики и формы из JSON больше не заменяют свойства игровых объектов.
JSON по-прежнему задаёт цель большого заказа. Комнаты лабораторий независимы.

Новый тип: дублировать один из пяти объектов, изменить Create и добавить
имя объекта в game_module_types(). Одного назначения родителя недостаточно.
Create должен только настраивать объект: генератор создаёт временный экземпляр
каждого типа, чтобы прочитать его drop_weight, и сразу его удаляет.
shape — прямоугольный массив: 0 пустота, 1 корпус, строка "LRD_1" — направления и тип порта.
Существующие вращение, провода и инвентарь работают через par_module.
Старые obj_module_1/2/3 сохранены как прототипы, в список выпадения не включены.

Строковые порты с типами:
shape = [["LRD_1", "R_2"], [0, 1]];
Это две разные клетки: у первой выходы слева, справа и снизу, тип 1;
у второй выход только справа, тип 2. L/U/R/D — лево/верх/право/низ.
Номер после подчёркивания — положительное целое число. Порядок и регистр
букв не важны. При вращении меняются направления, номер типа сохраняется.
Стороны одной клетки имеют общий тип; каждая сторона допускает один провод.
Все контакты модуля по-прежнему электрически связаны внутри модуля:
модуль с клетками разных типов может соединять цепи через свои контакты.
Провод соединяет только контакты одинакового типа. Это правило действует
при ручной и автоматической разводке, а также при замене занятого провода.
Несовместимые контакты не примагничиваются к рисуемому проводу.
Тип 1 рисуется оранжевым, тип 2 голубым; другие номера получают цвет автоматически.
Типы двух контактов платы задаются в Create устройства: board_port_types=[1,2].
По умолчанию board_port_types=[1,1]. Игровые формы могут использовать типы 1 и 2,
включая разные типы на одном модуле. Старые Cell.L/Cell.LRD и строки без суффикса читаются как тип 1.
Неверные строки (например, "R_0" или "LRD_1 R_2" в одной клетке) не создают контактов.

Переходники открываются после трёх заказов:
obj_module_adapter — Adapter 1-2, прямой: [["L_1", "R_2"]].
obj_module_adapter_corner — Corner adapter 1-2, угловой: [["U_1", 1], [0, "R_2"]].
У каждого ровно два контакта: один типа 1, второй типа 2. Внутри они соединены,
поэтому переходник позволяет продолжить цепь другим типом провода.
Все восемь характеристик равны 0, включая weight.
Переходники выпадают отдельно от обычных модулей: один бросок 33% на открываемый
девайс после третьего заказа. При успехе добавляется один случайный переходник
с равными шансами двух видов, сверх обычного лута (включая гарантированные наборы).
drop_weight=0 у обоих: они не занимают обычные 2–3 выпадения и не меняют их шансы.
Сначала размещаются обычные детали, затем бонус; разрешены повороты и попытка
второго вида, если первый не помещается. Если свободного места совсем нет, бонус
пропускается без удаления обычных деталей. Повторное открытие не даёт новый бросок.
Роботы используют тот же путь открытия и получают тот же бонус.
В лаборатории указан обычный вес 0 и отдельная справка о бонусе 33%; числовая
модель лаборатории не симулирует бонусные переходники и совместимость типов портов.
Старые лабораторные эксперименты получают переходники однократно без сброса
настроенных чисел и без восстановления ранее удалённых старых модулей.

Отрисовка питания: установленный модуль, не связанный с контактом 0 платы,
рисуется с 15% исходной насыщенности и яркостью 80%. Шейдер
shaders/shd_module_unpowered/shd_module_unpowered.fsh применяется только
к корпусу; контакты и подсветка остаются цветными. circuit_powered обновляется
в device_stats_update одновременно с характеристиками. В инвентаре и при
перетаскивании сохраняется обычная отрисовка.
