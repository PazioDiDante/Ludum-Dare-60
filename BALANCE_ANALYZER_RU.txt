ОБНОВЛЕНИЕ: РЕДАКТИРУЕМЫЙ БАЛАНС
Объекты игры дают только стартовые значения. В лаборатории можно менять требования,
статы, имя, вес выпадения и добавлять/удалять типы модулей. Это не меняет игровые объекты.
Сохранить/Загрузить сохраняют эксперимент. Сброс настроек (два нажатия) возвращает
стартовые значения из текущей сборки игры и удаляет экспериментальные модули.
Запуск анализа и возврат в комнату не перезаписывают изменения.
В Анализ → После заказа показаны остатки по успешным прогонам: деньги с наградой,
детали после расхода на заказ, купленные неразобранные устройства. Среднее, медиана,
минимум/максимум и вероятность наличия каждого типа рассчитываются по данным прогонов.
Ниже сохранены предыдущие описания; прежнее ограничение «поля только для чтения» снято.

ИСТОЧНИКИ ДАННЫХ — ОБЪЕКТЫ ИГРЫ
Каталог берётся из game_module_types() в scr_campaign. Этот же список использует obj_game.
Имя, stats и drop_weight читаются из Create каждого дочернего объекта par_module.
База и требования берутся из stats_base/stats_min/stats_max объекта obj_order.
Поля показаны в лаборатории только для чтения и обновляются перед запуском.
После правок GML перезапустите игру; «Обновить из игры» читает определения текущей сборки.
Экономика, число прогонов, ON/OFF и начальное количество деталей остаются настройками лаборатории.
«Лимит перебора модулей» (по умолчанию 8) — предел числового поиска, не лимит модулей в игре.
Геометрия платы и топология проводов по-прежнему не моделируются.
Старые сохранённые значения характеристик не переопределяют значения игровых объектов.

ОБНОВЛЕНИЕ ОСНОВНОГО СЦЕНАРИЯ
Главная кнопка теперь «Симуляция с нуля»: деньги=0, инвентарь пустой.
Используются заданные типы модулей, веса выпадения, требования и экономика.
Цикл: заработать → купить → разобрать → проверить заказ; повторять до успеха/лимита.
Один разбор = одна итерация. Вкладка Анализ > Игровой цикл показывает число разборов,
нажатия денег, время и распределение успехов. Это числовая модель без геометрии платы.
В Экономике переключатель «Начальный запас: учитывать» включает заданные qty и деньги
для следующих заказов. Иначе эти стартовые значения игнорируются.
«Проверить инвентарь» запускает прежний статический анализ имеющегося запаса.
Ниже приведены определения метрик и настройки дополнительных режимов.

АНАЛИЗАТОР БАЛАНСА — rm_balance (F6 со стола)

Изменения относятся только к лаборатории. Игровые объекты и третья комната не менялись.
Существующие bal_apply, bal_matches, проверка настроек и экономический симулятор сохранены.

КАК ПОЛЬЗОВАТЬСЯ
1. Заказ: задайте число слотов, базу, min/max восьми характеристик и допустимость OFF.
   Пустая граница означает отсутствие ограничения. Ноль является настоящей границей.
2. Модули: характеристики, количество в текущем инвентаре и вес случайного выпадения.
3. Анализ: результат пересчитывается после подтверждения поля Enter или кликом вне поля.
   Analyze Inventory запускает его вручную. Остановить отменяет текущие расчёты.
4. Сборки: переключатель Все / минимальные / почти; стрелки перебирают составы.
   Для каждого типа показано всего / ON / OFF, справа итоговые значения и границы.
5. Экономика > Эконом. прогон: прежняя модель покупки, заработка и времени.
   Её текстовый отчёт доступен в Анализ > Эконом. отчёт.

ОПРЕДЕЛЕНИЯ
Total: все уникальные наборы количеств типов и состояний ON/OFF из текущего запаса,
от min_installed до slots. Перестановки и индивидуальные номера одинаковых деталей
не учитываются. Свободные слоты не являются отдельными перестановками.
Valid: все требования выполнены. Success Rate = Valid / Total; при Total=0 — N/A.
Minimum Modules: наименьший размер рабочей сборки; без решений — N/A.
Near Misses: нарушена ровно одна характеристика. Диапазон считается одним требованием.
Отклонение — расстояние до нарушенной границы в исходных единицах характеристики.
Для каждого типа нарушения хранятся минимум, среднее и максимум отклонения.
Constraint Pressure: нарушившие данную характеристику / Total; стрелки — число
нарушений нижней и верхней границы. Нарушения нескольких параметров могут пересекаться.
Module Usage: доля Valid, содержащих тип хотя бы один раз. ON — доля с включённым типом.
Minimal — доля минимальных сборок, в которых тип присутствует. Нет знаменателя — N/A.
Вес учитывается для всех установленных экземпляров, остальные свойства — только ON.

Минимальная по включению сборка: ни одно строгое подмножество с сохранением ON/OFF
не выполняет заказ и условия слотов. Проверяются и удаления нескольких деталей сразу.
Это отличается от глобального Minimum Modules: минимальные сборки бывают разных размеров.
Лишние модули влияют на Total/Valid, но не порождают новых минимальных решений.

ПРОГРЕССИЯ
Этап 0 всегда означает стартовый инвентарь. Детали не тратятся на выполнение заказов
между этапами: анализируется доступность одного и того же заказа.
Случайная добыча: 1..20 устройств, заданные loot min/max и относительные веса типов,
повторы типов разрешены; 1..1000 прогонов, воспроизводимый Seed. Нулевые веса не выпадают.
Составы устройств: до 16 конкретных исходных устройств. Каждая строка добавляет добычу
к предыдущему инвентарю. Количества через запятую соответствуют порядку типов во вкладке
Модули; пропуски не допускаются. Например для A,B,C строка 2,0,1 означает два A и один C.
После изменения списка типов проверьте все строки составов; неверная длина отвергается.
Minimum Devices ищется среди ЛЮБЫХ подмножеств этих устройств, включая пустое, а не
только последовательных префиксов. Начальные детали доступны бесплатно. Каждое
заданное устройство можно разобрать один раз. Если решения нет — «Нет решения».
Состояния инвентаря: строки задают полный запас каждого этапа, заменяя предыдущий.
Это подходит для этапов производства, расхода деталей и открытия новых типов.
Для random и снимков инвентаря Minimum Devices = N/A: составы исходных устройств неизвестны.

Зелёная кривая: доля прогонов, где существует хотя бы одно решение.
Голубая кривая: среднее количество Valid, своя шкала с указанным максимумом.
Таблица: средние Valid, средний Success Rate и доступность; n — обработанные прогоны.
Средние включают только завершённые точные переборы. При Total=0 Success Rate — N/A.
Если часть переборов ограничена и решение не обнаружено, доступность показывается
интервалом [найденные успехи/n .. (успехи+неизвестные)/n], а не ложным нулём.
Random — эмпирическая оценка по прогонам, не математическое доказательство невозможности.
Изменение настроек сбрасывает старую прогрессию; её нужно запустить заново.

ПРЕДУПРЕЖДЕНИЯ
Выводятся только по полному анализу текущего инвентаря. Пороги редактируются в Прогрессии.
NO SOLUTIONS: Valid=0.
TOO EASY: Success Rate >= порога (по умолчанию 25%).
RARELY USED MODULE: доступный тип присутствует менее чем в 5% Valid.
POSSIBLE BOTTLENECK: давление >=80% либо тип присутствует во всех Valid.
Это настраиваемые диагностические сигналы, не доказательство плохого баланса.

ЛИМИТЫ И ТОЧНОСТЬ
Сохраняется существующий предел заказа 1..8 слотов, каталог до 40 типов.
Каждый анализ: до 300000 узлов и 30000 рабочих сборок. Первые 200 near misses доступны
для просмотра; их полное число и статистика отклонений считаются независимо от списка.
Поиск минимальных наборов / Minimum Devices ограничен 3000000 сравнениями.
Расчёты идут порциями по кадрам и отменяются кнопкой Остановить. limited/stopped означает
частичный результат. Предупреждение NO SOLUTIONS не выводится по неполному перебору.
Геометрия и топология проводов не моделируются: используется существующая числовая
модель ON/OFF. Прогрессия учитывает наличие деталей, экономический отчёт — деньги/время.
