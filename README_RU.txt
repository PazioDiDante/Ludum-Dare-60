ШАБЛОН УСТРОЙСТВ: ОДНО АКТИВНОЕ УСТРОЙСТВО НА ЭКРАНЕ

В меню выберите Remote control или Radio. Снимите винты ЛКМ.
При первом открытии генерируются модули: случайное количество, типы и позиции.
ЛКМ подбирает модуль: он следует за мышью с привязкой к клеткам и сохранением клетки захвата.
Следующий ЛКМ ставит его на допустимое место; при недопустимом месте модуль остаётся в руке.
ПКМ поворачивает подобранный модуль на 90 градусов по часовой стрелке. Q или средняя кнопка мыши отменяет подбор. Pause -> Restart device создаёт новое содержимое.
Pause -> Choose device удаляет текущее устройство и возвращает выбор. Прогресс не сохраняется.

КАК ДОБАВИТЬ УСТРОЙСТВО
1. Создайте объект с родителем par_device, без собственных Draw/Step.
2. В Create: event_inherited(); затем настройки (см. obj_remote/obj_radio).
3. Последней строкой вызовите device_build();
4. Добавьте тип и подпись в device_types/device_labels в Create obj_game.
   Меню рассчитано на несколько кнопок; для большого каталога понадобится прокрутка.

НАСТРОЙКИ В CREATE ПОТОМКА
device_name — название.
half_w/half_h — половины размеров корпуса для временной графики и области клика.
screw_positions = [[dx,dy],...] — произвольное число винтов, смещения от центра устройства.
source_cell_size = 16 — размер клетки в исходном спрайте.
board_scale = 3 — желаемое увеличение. Автоматически уменьшается, чтобы плата помещалась в окно.
draw_scale — фактический масштаб; cell_size = source_cell_size * draw_scale — вычисленный экранный размер клетки.
board_shape — прямоугольный массив строк: 1 доступная клетка, 0 вырез/отверстие.
board_offset = [dx,dy] — смещение центра платы от центра устройства.
board_mask_sprite — необязательный спрайт маски; если задан, заменяет board_shape.
board_sprite — необязательное изображение открытой платы.
cover_sprite — необязательное изображение крышки, origin в центре устройства.
module_pool — массив типов объектов-потомков par_module.
module_min/module_max — запрашиваемый диапазон количества (целые 0 <= min <= max).
layout_seed = -1 — случайно; число >=0 — повторяемая раскладка для отладки.

ФОРМА ПЛАТЫ ИЗ СПРАЙТА
Можно использовать будущий рисунок платы. Импортируйте одно кадровое изображение с прозрачным фоном.
В Sprite Editor задайте Collision Mask -> Type: Precise, Bounding Box: Automatic.
board_mask_sprite = spr_my_board; board_sprite = spr_my_board;
Размер холста делайте кратным source_cell_size (по умолчанию 16). У маски и рисунка должны совпадать размеры холста.
При создании устройства проверяется центр каждой клетки: внутри точной маски — 1, снаружи — 0.
Неполные клетки справа и снизу запрещены. Прозрачные отверстия становятся запрещёнными клетками.
Это дискретизация по центру, а не проверка всего квадрата: на кривой границе клетка может выступать за рисунок.
Если рисунок содержит мелкие прозрачные детали или нужно точно контролировать клетки,
нарисуйте отдельный простой mask sprite (непрозрачные доступные области на прозрачном фоне).
Рисунок в board_sprite может быть более подробным, чем board_mask_sprite.
obj_board_mask — временный невидимый помощник для чтения маски, удаляется сразу после построения массива.
Спрайт не перечитывается каждый кадр. Поворот/масштаб платы не предусмотрен.

МОДУЛИ
Родитель par_module. В Create потомка: event_inherited(); shape = [...]; interaction_label = "...";
module_color = ...; при необходимости sprite_index = spr_module.
shape[row][col]: 0 пусто; 1 корпус; Cell.L/U/R/D корпус с портом на соответствующей стороне.
Порты должны смотреть наружу формы. Пока один порт на клетку. Соединения ещё не реализованы; поворот на 90 градусов доступен по ПКМ.
grid_col/grid_row — позиция формы. device — ссылка на устройство, назначается генератором.
board[row][col] хранит noone или ID занявшего клетку модуля; board_shape задаёт допустимые клетки.
Перемещайте через board_place(module,col,row), не меняйте x/y напрямую.
У спрайта модуля origin должен быть слева сверху; размеры должны соответствовать форме и source_cell_size (16 пикселей на клетку).
Спрайт модуля увеличивается автоматически вместе с платой; origin учитывается.
Create модулей должен только задавать данные: генератор создаёт временных кандидатов и удаляет неподходящих.

КАК РАБОТАЕТ РАНДОМ
Сначала выбирается требуемое количество. Для очередного модуля находятся допустимые позиции всех типов.
Случайно выбирается один из помещающихся типов и одна его позиция. Повторы типов разрешены.
Если места ни для одного типа нет — генерация останавливается и показывает placed/requested.
Это простой жадный алгоритм: он не гарантирует минимум при тесной плате и не ищет идеальную упаковку.
Он гарантирует отсутствие наложений и выхода на запрещённые клетки. Решаемость будущей головоломки не проверяется.
Форма/порты модуля не рандомизируются; при ручном вращении форма и направления портов поворачиваются вместе. При закрытии меню и возврате Resume раскладка сохраняется;
при Restart или новом выборе устройства — создаётся заново.

ОСНОВНЫЕ ФАЙЛЫ
par_device: общая логика крышки, кликов, отрисовки, удаления деталей.
obj_remote/obj_radio: только настройки конкретного устройства.
scr_device: построение устройства, чтение маски, случайная раскладка.
scr_board: проверка и размещение модулей.
par_module: общие клики и отрисовка; obj_module_1/2/3 — конкретные формы.
obj_game: выбор устройства, меню и пауза.


ПРИМЕР СООТВЕТСТВИЯ
Спрайт платы 128x64, клетка исходника 16x16: сетка 8x4.
При draw_scale=3 клетка на экране 48x48, плата 384x192.
Спрайт платы 512x256: сетка 32x16; увеличение автоматически ограничивается размером окна.
Маска считывается в исходных пикселях, а изображение, сетка, модули и клики используют экранный размер.
Крышка увеличивается отдельно до размеров корпуса с сохранением пропорций и центрированием.
Позиции винтов по-прежнему задаются экранными смещениями относительно центра устройства.


ПОДБОР МОДУЛЕЙ
scr_board: board_pick, board_drag_update, board_drop, board_cancel.
grab_col/grab_row — клетка формы, за которую взяли модуль (оффсет).
preview_col = floor((mouse_x-board_x)/cell_size)-grab_col; аналогично для строки.
x/y — текущее положение картинки. grid_col/grid_row — последнее подтверждённое положение.
До установки старые клетки зарезервированы в board, что гарантирует возврат по Q/средней кнопке мыши.
Зелёная обводка — можно поставить; красная — пересечение, вырез платы или выход за границы.
Подобранный модуль рисуется поверх остальных. Его кнопки обрабатываются раньше других предметов.
Кнопку мыши удерживать не нужно. Пауза замораживает перенос; после Resume он продолжается.
Меню имеет приоритет: нажатие Pause не устанавливает модуль. Вспомогательные тексты на экран не добавлены.


ВРАЩЕНИЕ ПОДОБРАННОГО МОДУЛЯ
ПКМ: 90 градусов по часовой стрелке. ЛКМ: установка. Q/средняя кнопка мыши: отмена.
board_rotate в scr_board создаёт новый массив: rotated[col][old_height-1-row].
Направления портов U -> R -> D -> L -> U. Пустоты и корпус сохраняются.
Клетка захвата поворачивается вместе с формой и остаётся под курсором.
Поворот в занятое место допускается как красный предпросмотр; установить туда нельзя.
rest_shape/rest_rotation сохраняют ориентацию при подборе; отмена возвращает её и старую позицию.
rotation_steps (0..3) определяет отрисовку спрайта. Не задавайте image_angle вручную.
У спрайта исходный холст должен соответствовать неповёрнутой форме: ширина/высота формы * source_cell_size.
module_sprite_offset учитывает origin и изменение габаритов спрайта при повороте.


СОЕДИНЕНИЯ ПОРТОВ
ЛКМ по оранжевому контакту начинает линию до мыши. ЛКМ по контакту ДРУГОГО модуля завершает её.
ЛКМ по корпусу по-прежнему подбирает модуль. Пока линия начата, клик мимо контакта не подбирает предмет.
ПКМ, Q или средняя кнопка мыши отменяет незавершённую линию. Меню и пауза имеют приоритет.
Типы, направления, расстояния и пересечения проводов пока не ограничены.
Один контакт может иметь только один провод. Занятый второй контакт заменяет старый провод новым.

В par_module.Create: connections = [];
Элемент connections: { module: ID_другого_модуля, own_port: ..., other_port: ... }.
Порт: { module: ID_владельца, col: колонка_исходной_формы, row: строка_исходной_формы }.
Это координаты ДО поворота: идентичность порта сохраняется при вращении.
port_current(port) возвращает актуальные col, row, direction и экранные x/y.
При переносе, вращении и отмене провода следуют за контактами автоматически.
Устройство хранит wires для однократной отрисовки каждой линии.
Основной код в scr_connections. Draw obj_game рисует линии над модулями, под меню.
CleanUp par_module удаляет ссылки у соседей и линии устройства. В потомках с собственным CleanUp вызывайте event_inherited().
ЛКМ по занятому контакту (когда линия ещё не начата) удаляет его провод с обоих концов и начинает новую линию от нажатого контакта.
Q/средняя кнопка отменяет новую линию, но не восстанавливает удалённый провод. Клик по самой линии не используется.
При выборе второго конца занятый порт заменяет существующий провод: старые записи удаляются у обоих прежних участников, новый провод записывается у новых участников.
Проверки другого модуля и того же устройства выполняются ДО удаления старой связи.
ПКМ при натягивании провода отменяет его; при переносе модуля по-прежнему вращает модуль.
wire_for_port проверяет занятость; wire_disconnect удаляет ровно одну связь из wires и обоих connections.


ИНВЕНТАРЬ
Справа 3 x 4 ячейки, одна ячейка на модуль. ЛКМ по пустой ячейке кладёт выбранный модуль; ЛКМ по занятой без выбранного модуля подбирает его. Q/средняя кнопка возвращает его в исходную ячейку. Занятая ячейка не принимает другой модуль. ПКМ вращает выбранный модуль.
Помещение в инвентарь удаляет провода и освобождает плату. Хранимые модули сохраняются при смене устройства, но не после закрытия игры.
Настройки в obj_game Create: inventory_cols, inventory_rows, inventory_size, inventory_x/y. Логика и миниатюры: scr_inventory. Без спрайта миниатюра рисует форму и порты.

ПОРТЫ ПЛАТЫ
При открытии крышки создаются два неподвижных порта на случайных внешних границах board_shape (в том числе полученной из спрайта). Они рисуются снаружи клеток, не занимают места модулей и не перегенерируются при переносе модулей. У пустой платы портов нет.
ЛКМ по порту платы начинает провод; второй клик по порту модуля завершает его. Можно начинать и от модуля. Действуют обычные правила замены занятого порта и отмены по ПКМ/Q/средней кнопке. Перенос модуля в инвентарь удаляет его соединения с платой.
Данные: par_device.board_ports; генерация/отрисовка/координаты: board_ports_generate, board_ports_draw, board_port_current в scr_connections. Соединения платы хранятся в par_device.connections.

НЕПРЕРЫВНАЯ ЦЕПОЧКА
par_device.circuit_connected — true, если порт платы 0 соединён с портом 1 через один или несколько модулей. Все порты одного модуля считаются связанными внутри него. Пересечения проводов и соседство модулей не создают соединений.
circuit_update в scr_connections обходит связанные модули с защитой от циклов. Запускается только после добавления/удаления провода (включая удаление модуля и перенос в инвентарь). Замена занятого провода проверяется один раз после завершения замены. Пустой черновик, отмена без удаления, перемещение и вращение не запускают проверку.
circuit_check_count — счётчик запусков для отладки. Начальное circuit_connected = false. Результат можно читать без повторного обхода; интерфейс и автоматическая победа пока не добавлены.

СТОЛ ВМЕСТО СТАРТОВОГО МЕНЮ
На фоне spr_table в центре показан один случайный девайс. ЛКМ по его маленькому спрайту начинает разборку. Пульт использует spr_remote_small, радио — spr_radio_small. Масштаб миниатюры: table_scale в obj_game Create. Соответствие объектов и спрайтов: device_types и table_sprites в том же событии.
GameMode.Menu теперь обозначает стол. Меню выбора устройств не рисуется. Пауза сохранена, Back to table возвращает на стол; инвентарь сохраняется по прежним правилам. Спрайт spr_table назначен слою Background комнаты Room1 (depth 100), позади устройства.

ЛАБОРАТОРИЯ БАЛАНСА: F6 на столе открывает rm_balance. Настройки заказа, каталога модулей, цен, времени и прогонов редактируются в UI. Подробное описание допущений и сохранения: BALANCE_LAB_RU.txt.

РУЧНОЙ ЭКСПЕРИМЕНТ: F7 на столе или в лаборатории баланса открывает третью комнату rm_manual. Каталог изначально пуст. Создание своих модулей, цель по четырём характеристикам, ручной заработок/покупка и перенос модулей кликом. Инструкция: MANUAL_LAB_RU.txt.

ИГРОВОЙ ЦИКЛ ПОКУПКИ И ЗАКАЗА
Стартовая комната Room1: 50 монет, заказ-микроволновка и один бесплатный закрытый девайс для разбора. Первые три заказа: микроволновка (100 монет), плеер (125), дрон (150). Используются их наборы спрайтов small/board/cover. Купить следующий девайс — 25 монет за одну случайную модель (пульт/радио). Все покупки отдельно сохраняются на столе; всего доступно 6 мест, включая стартовый девайс.
Клик по маленькому устройству открывает разбор. Первый девайс всегда содержит две обычные батарейки, кулер и стабилизатор. Второй — двойную батарею, катушку (coil) и универсальный блок (universal). Набор закрепляется при получении устройства и сохраняется независимо от порядка открытия и разбора роботом. Этих семи деталей достаточно для первого заказа: энергия 9, тепло 4, стабильность 3, вес 7. Начиная с третьего девайса после винтов появляются обычные 2–3 случайные детали. Имя и четыре характеристики доступны при наведении на деталь, включая инвентарь.
«На стол» сохраняет устройство, оставшиеся детали и соединения. «Завершить разбор» удаляет только активное маленькое устройство. Если остались детали внутри — необходимо повторное нажатие «Да, выбросить остатки». Сохранённый инвентарь остаётся. Инвентарь листается стрелками, новая страница добавляется по мере заполнения.
Кнопка Get plate выдаёт одну spr_plate на стол. Нажатие на плату запускает ручную пайку: 5 секунд и +20 монет (2.5 секунды с Faster income). Робот-паяльщик забирает свободную плату кнопкой spr_play и выдаёт +20 монет через 10 секунд. По завершении плата расходуется. Без платы работа не начинается; одновременно на столе не более одной. Пауза останавливает таймеры, отключение энергии сохраняет плату и прогресс робота. Подробности: PLATE_RU.txt.
Первые три больших заказа сохраняют заданные требования и награды 100/125/150. После третьей сдачи открываются шесть новых модулей скорости/эффективности. Заказы 4–6 — телефон, Game и компьютер второго тира; с седьмого выдаётся obj_big_order второго тира: энергия 3..7, тепло 0..5, стабильность 0..5, скорость 2..5, награда 300; без требований к весу и эффективности. Пока этот проверенный заказ повторяется с точными границами из предоставленной копии баланса. Очередь продолжается без конца. Экземпляр хранит требования, награду и спрайты маленького вида, корпуса и платы. Плата изначально пуста; установите детали из инвентаря и соедините порты. Характеристики учитываются у модулей в сети любого из двух контактов платы; вес — у всех установленных. Для сдачи нужны замкнутая цепь и выполнение требований. Установленные детали уходят вместе с заказом. Модули и настройки второго тира: TIER2_BALANCE_RU.txt.
Каталог и цель читаются из manual_modules.json в папке сохранений. В сборку включена резервная копия пользовательского файла datafiles/campaign_catalog.json (5 типов). Обе лаборатории доступны по F6/F7 со стола. Ход игры хранится в памяти текущего запуска.
Код цикла: scr_campaign. Параметры прототипа: 50 старт, 25 покупка, 5 секунд / 10 монет заработок. Процедурные прямоугольники модулей можно позже заменить спрайтами.

ШРИФТ И ЯЗЫК ИНТЕРФЕЙСА
Основной шрифт: Edit Undo (обычный editundo.ttf), Brian Kent.
TTF и исходный текст автора включены в datafiles/fonts/edit-undo и в сборку.
Установка шрифта в Windows не требуется. Текст рисуется без сглаживания.
Размеры: интерфейс 18 px, статус цепи 24 px, лаборатории 16 px.
Создание и восстановление основного шрифта: scripts/scr_font/scr_font.gml.
Поскольку Edit Undo не содержит кириллицы, встроенный интерфейс, сообщения,
названия модулей, магазин и обе лаборатории переведены на английский.
Пользовательские файлы настроек в папке сохранений не изменяются.

ДЕБАГ: debug_tools=true даёт 1000 монет, 50 шестерёнок и бесконечные образцы всех 16 видов деталей в инвентаре, включая второй тир и переходники. При взятии создаётся отдельная деталь, образец остаётся. Отмена или возврат копии в инвентарь удаляет копию; обычный найденный лут перемещается как прежде.
Старт всегда с первого заказа: Microwave → Player → Drone → Telephone → Game → Computer. Переключатель debug_start_tier2 удалён. На экране заказа кнопка Skip (debug) без награды сразу открывает следующий заказ, сохраняя инвентарь. При debug_tools=false бесконечных образцов и пропуска нет, стартовые ресурсы обычные.

ЗВУКИ (2026-10-18)
Пять исходных WAV скопированы без изменения в sounds/ и зарегистрированы в проекте.
snd_click: кнопки, магазин, переходы, пауза.
snd_vint: цикл во время ручного откручивания; пауза/потеря фокуса приостанавливает, отмена/завершение останавливает.
snd_modul_take_place: подбор, установка, поворот, перенос в инвентарь и ручные действия с проводами.
snd_remove_cover: открытие видимой крышки активного прибора после винтов.
snd_coin: положительный доход за ручную пайку, пайку робота, продажу и сдачу заказа.
Генерация, автоматическое размещение/соединение, скрытая разборка и симуляции лабораторий звуки действий не воспроизводят.
Общая логика: scripts/scr_audio. В obj_game Create sfx_enabled включает или выключает эффекты.
ДОПОЛНЕНИЕ К ЗВУКАМ (2026-10-18)
snd_generator_break: однократно при новой поломке генератора (исходник snd_generator break.wav).
snd_solider: общий цикл ручной пайки и работающих паяльных роботов; пауза/потеря фокуса приостанавливает, отсутствие работы или питания останавливает. Один экземпляр независимо от числа роботов.
snd_imposible: отклонённая попытка действия игрока: размещение/соединение, покупка, запуск/питание робота, управление генератором, сдача/продажа. Автоматические повторы не озвучиваются.
snd_device_ready: переход активного прибора к выполнению всех требований с замкнутой цепью. Повторное открытие готового прибора не повторяет сигнал; генератор и производственные платы исключены.
snd_robotDone: успешное завершение пайки, переработки, сборки и разборки роботом. Монетка при заработке сохранена.
Все десять WAV сохранены без изменения звуковых данных.
НАСТРОЙКА ПОВТОРОВ И ПИТЧА (2026-10-18)
Винт воспроизводится короткими отдельными импульсами раз в 0.30 секунды вместо непрерывного цикла. Интервал задаётся screw_sound_interval в obj_game Create; пауза сохраняет оставшееся время, отмена/завершение сбрасывает его. После задержки кадров импульсы не догоняют таймер пачкой.
Случайный питч: винт 0.90..1.10, клик 0.94..1.06, модуль 0.92..1.08. Используется отдельный генератор случайных чисел для аудио; игровая случайность не затрагивается. Остальные звуки сохраняют исходный питч.
