BASE GAME — нейтральная основа для GameMaker / Ludum Dare
Подготовлено 16 октября 2026.

БЫСТРЫЙ СТАРТ

1. Откройте Base Game.yyp в GameMaker LTS 2026 (исходный IDEVersion 2026.0.0.16).
   Если проект был открыт во время внешних изменений, перечитайте его с диска:
   не сохраняйте поверх новых ресурсов старое состояние редактора.
2. Выберите Windows / VM и нажмите F5 (Run в IDE).
3. В окне игры нажмите Enter. Голубой прямоугольник — игрок,
   серые — стены, оранжевые — тестовые интерактивные объекты.
4. WASD / стрелки — движение; E / Space — взаимодействие;
   Esc / P — пауза; F1 — отладочная информация.
   На паузе: вверх/вниз + Enter. Возврат в меню сохраняет состояние комнаты.
   Reset test room пересоздаёт комнату и возвращает стартовое меню.
   F5 внутри игры сбрасывает комнату только при включённом debug.

ЧТО В ПРОЕКТЕ

15 ресурсов: 1 комната, 3 скрипта, 8 объектов, 3 технических спрайта. Расширений,
звуков, сетевых зависимостей и игрового содержания под тему нет.
Room1: 960 x 540; obj_game, 6 стен, игрок и 2 переключателя размещены
в редакторе комнаты. scr_test_room удалён. Создания уровня кодом нет.
Перетаскивайте obj_wall, obj_player, obj_switch на слой Instances.
Размер стены меняйте инструментом Scale в редакторе: физический размер
берётся из масштаба экземпляра при Create. Поворот стен не поддерживается;
оставляйте Rotation = 0. Центр спрайта совпадает с x/y.
Сохраняйте ровно один obj_game и один obj_player. obj_game должен быть
первым в Instance Creation Order. Технические спрайты — цветные квадраты.
GUI имеет фиксированные логические размеры 960 x 540.
Все .yy/.yyp загружены и связаны штатным компилятором GameMaker.
Сборка Windows VM прошла на runtime 2026.0.0.23.
Подробные границы проверки — VALIDATION_RU.txt.

ИЕРАРХИЯ

par_entity
  par_actor
    obj_player
  par_solid
    obj_wall
    par_interactable
      obj_switch
obj_game — отдельный контроллер.

Родители — соглашение для наследования; GameMaker не запрещает размещать их
в комнате. Обычно размещайте только конкретные объекты-потомки.
В переопределённом Create сначала вызывайте event_inherited().
Draw родителя рисует спрайт, если он назначен, иначе тестовый прямоугольник.
В собственном Draw используйте event_inherited(), если нужна эта отрисовка.

ВВОД — scr_input

Action — перечисление действий, а не клавиш.
input_down(Action.Left) — действие удерживается.
input_pressed(Action.Interact) — переход из отпущенного в зажатое.
input_released(Action.Interact) — отпущена последняя привязанная клавиша.
input_axis(Action.Left, Action.Right) — -1, 0 или +1.
Противоположные направления взаимно компенсируются.

Назначить несколько клавиш:
    input_bind(Action.Interact, [ord("E"), vk_space, ord("F")]);
Отключить действие:
    input_bind(Action.Interact, []);
Добавить действие: добавьте имя перед Count в enum Action и привязку в input_init.
Клавиши ord должны использовать заглавные латинские буквы.
Привязки хранятся в памяти; сохранения настроек на диск и UI переназначения нет.

input_update вызывается один раз в Begin Step obj_game, в том числе на паузе.
Читайте результат в обычном Step; не вызывайте повторный update в игроках.
Обрабатывается совокупное состояние: A удерживается + нажата Left не даёт
нового pressed; отпускание A при удержании Left не даёт released.
Переназначение на уже удерживаемую клавишу не создаёт pressed.
Очень короткий нажим и отпускание между двумя опросами может не обнаружиться.
Необязательный параметр _read_key у input_update/input_bind — функция
определения состояния клавиши. По умолчанию keyboard_check; в тестах
используется предсказуемый источник, не ввод в ОС.

ДВИЖЕНИЕ И СТОЛКНОВЕНИЯ — scr_world

Вызов actor_move(dx, dy) из экземпляра актёра.
dx/dy — расстояния в пикселях за текущий кадр, а не скорость.
move_speed у игрока — 180 пикселей в секунду.
Диагональ нормализована. global.dt — delta_time в секундах, максимум 0.05.
При сильных просадках игра замедлится вместо огромного скачка координат.

Физическая форма: прямоугольник с центром x/y и полуразмерами half_w/half_h.
У препятствий-потомков par_solid проверяется blocks_motion.
Сначала разрешается X, затем Y. Проверяется полный путь, что предотвращает
проскок через неподвижную тонкую стену при большом перемещении.
Дробные координаты поддерживаются. При касании стен разрешено скольжение.

Это простая AABB-система, не физический движок. Здесь НЕ используются
галочка Solid, sprite mask, Collision events или tilemap collision.
Масштаб из редактора считывается при Create. Последующее изменение
image_xscale/image_yscale и смена спрайта не меняют форму столкновения.
Поворот image_angle также не поворачивает прямоугольник столкновения.
Не создавайте актёра внутри стены: выталкивание из пересечения не реализовано.
Движущиеся платформы, наклонные поверхности и столкновения актёров между собой
не реализованы. Алгоритм перебирает препятствия и рассчитан на небольшую игру.

ВЗАИМОДЕЙСТВИЕ — МЕТОДЫ ЭКЗЕМПЛЯРА

У par_interactable есть interaction_enabled, interaction_label,
can_interact(actor) и interact(actor). Дальность — между центрами объектов.
interaction_find(actor, range) выбирает ближайший доступный объект
в радиусе, без стены между его центром и игроком. Направление взгляда не нужно.
Сам целевой объект не перекрывает проверку видимости.
Равная дальность разрешается порядком экземпляров; приоритетов нет.

Новый интерактивный объект: создайте потомка par_interactable, в Create:
    event_inherited();
    blocks_motion = true; // false для проходимого объекта
    interaction_label = "Use";
    interact = function(_actor) {
        if (!can_interact(_actor)) return false;
        // Здесь действие этого экземпляра.
        return true;
    };
При необходимости переопределите can_interact таким же методом.
Метод привязан к экземпляру цели, поэтому его переменные относятся к цели.
Пример obj_switch меняет только свой цвет и отладочную надпись.

АНИМАЦИИ — scr_animation

anim_init() уже вызывается родителем par_entity.
После создания собственного спрайта (например, spr_idle) вызовите:
    anim_set(spr_idle, 8, true);
Для одноразовой анимации:
    anim_set(spr_action, 12, false, true);
Это имена ваших будущих ресурсов; в основе таких спрайтов нет.

anim_set(sprite, fps, loop, restart=false) не сбрасывает тот же спрайт,
если restart=false; fps и loop при этом обновляются.
Чтобы повторить завершённую одноразовую анимацию, передайте restart=true.
anim_tick(global.dt) — один раз в активном Step; у игрока уже есть вызов.
image_speed всегда 0: кадры продвигаются нашим счётчиком.
Не меняйте image_index/image_speed вручную при использовании этих функций.
Для поворота/отражения графики можно менять image_angle/image_xscale.

После anim_tick:
    anim_frame()        — целый номер текущего кадра, начиная с 0;
    anim_last()         — сейчас показан последний кадр;
    anim_entered(2)     — в этом обновлении пересечён кадр 2;
    anim_ended          — в этом обновлении пересечён конец анимации;
    anim_done           — одноразовая анимация завершена.

anim_last НЕ означает, что последний кадр уже отыграл свою длительность.
anim_entered учитывает пропущенные кадры и переход через начало цикла;
возвращает булево значение, а не число пересечений за большой шаг.
Начальный кадр 0 при anim_set не вызывает anim_entered(0).
Если нужны действия на старте анимации, выполните их вместе с anim_set.
Скорость только неотрицательная. Отрицательное/обратное воспроизведение не включено.

ПАУЗА И UI

obj_game управляет GameMode.Menu / Play / Pause.
Потеря фокуса окна ставит Play на паузу; продолжение — вручную.
window_has_focus применим к Windows/macOS/HTML5/GX; другие платформы не проверены.
UI остаётся активен. Игровой код должен начинаться с:
    if (!game_running()) exit;

Это программная пауза, а не остановка всего движка. Новые Alarm, встроенные
speed/hspeed/vspeed, paths, physics, sequences, particles и audio сами не
замораживаются. Для таймеров используйте уменьшение на global.dt в активном Step.
Новые актёры должны самостоятельно вызывать anim_tick только при game_running().
В основе таких автономных систем нет.

Меню рисуется в Draw GUI; логика выбора находится в Begin Step.
Мышь и геймпад не подключены. Для небольшого джема это несколько читаемых
условий вместо отдельной UI-архитектуры. Текст интерфейса ASCII/английский,
чтобы работать со встроенным шрифтом без дополнительного ресурса font.

КАК НАЧАТЬ СВОЮ ИГРУ

1. Сохраните отдельную копию основы до начала работы над темой.
2. После старта события добавляйте собственные правила, графику, звук и уровни.
3. В новой комнате нужен слой Instances и ровно один obj_game.
   Разместите собственные экземпляры объектов на слое Instances.
   Контроллер не persistent: каждая комната начинает своё состояние заново.
   Для переноса прогресса между комнатами потребуется отдельное решение.
4. Для статического препятствия используйте потомка par_solid.
5. Для новой анимации назначьте спрайт с центром координат в центре изображения
   или адаптируйте Draw под свой origin; физический прямоугольник остаётся прежним.
6. Перед сдачей выключите debug и удалите ненужные тестовые ресурсы.
7. Прочитайте LUDUM_DARE_RULES_RU.txt; подготовьте архив исходного проекта.
